# Довідник полів

Опис усіх полів у TSV файлах та їх відповідність полям у Jira.

---

## Work item ID

Унікальний числовий ідентифікатор тікету **в межах одного TSV файлу**.

```
1, 2, 3, 4 ...
```

> [!IMPORTANT]
> ID мають бути унікальними в межах файлу. При злитті через `merge.py` глобальні ID генеруються автоматично.

---

## Parent

Work item ID батьківського тікету. Використовується для побудови ієрархії.

```
# Epic з ID=1, Story під ним:
Work item ID  Parent  Work type  Summary
1                     Epic       Тиск на НАБУ і САП
2             1       Story      Встановлення спецобладнання без санкції суду
```

- Epic — не має Parent (поле порожнє)
- Story / Task — Parent вказує на Epic
- Subtask — Parent вказує на Story або Task

---

## Work type

Тип тікету. Визначає місце в ієрархії.

| Тип | Коли використовувати |
|-----|----------------------|
| `Epic` | Велика тема або серія пов'язаних подій |
| `Story` | Конкретна подія, нова діяльність, факт |
| `Task` | Організаційна або технічна дія |
| `Bug` | Неправомірне виконання процесу, порушення закону |
| `Subtask` | Частина Story/Task, якщо є підзадачі |

---

## Summary

Коротка назва тікету. Відображається скрізь у трекері.

**Формат:** `[Дія] + [Об'єкт]`

```
✅ Затримати Германа Галущенка
✅ ДБР не відкрило службове розслідування щодо витоку фото Шабуніна
✅ Апеляційна палата ВАКС засудила Гунька до 4 років ув'язнення
❌ Проблема з розслідуванням
❌ Корупція в ДБР
```

- Максимум **200 символів**
- Одне речення
- Без крапки в кінці

---

## Description

Розгорнутий опис тікету. Має три обовʼязкові блоки:

```
* Контекст: що сталося, хто задіяний, чому важливо
* Джерело: посилання або назва документа / публікації
* Acceptance Criteria: що має статися, щоб вважати тікет виконаним
```

Додатково для Bug:
```
* Кроки відтворення: як перевірити порушення
```

**Приклад:**
```
* Контекст: у липні 2025 ДБР провело обшуки без ухвал суду; троє детективів затримані
* Джерело: заява керівника НАБУ від 15.07.2025 — https://nabu.gov.ua/...
* Acceptance Criteria: службове розслідування зареєстровано; винні ідентифіковані
```

> [!NOTE]
> У TSV файлі переноси рядків у Description замінюються на `\n`.

## Priority

Реальна важливість та терміновість.

| Значення | Коли використовувати |
|----------|----------------------|
| `Highest` | Критичні правопорушення: незаконні затримання, тиск на суддів, збройні злочини |
| `High` | Серйозні порушення: корупційні схеми, перешкоджання слідству |
| `Medium` | Важливі але не критичні: процесуальні порушення, бездіяльність |
| `Low` | Інформаційні та адміністративні дії |

---

## Labels

Теги для фільтрації та пошуку. Через кому, без пробілів.

```
NAKU_SAP, Shabunin, DBR, AOZ, VAKS, Galushchenko, Prokuror
```

Рекомендовані категорії:
- **Установа:** `DBR`, `NABU`, `SAP`, `VAKS`, `SBU`, `Rada`
- **Справа:** `Shabunin`, `Galushchenko`, `Midas`
- **Тема:** `AOZ`, `VKKS`, `Reform`

---

## Assignee

Відповідальний виконавець. У контексті цього проекту — державний орган, суд або посадова особа.

```
DBR          ← Державне бюро розслідувань
NABU         ← НАБУ
Court_VAKS   ← Суд (ВАКС)
Galushchenko ← конкретна особа
```

Якщо виконавець невідомий — поле залишається порожнім.
